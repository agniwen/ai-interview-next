# 简历 PDF 预览选型

调研日期：2026-11-06。范围是点击文件名后在站内查看私有 PDF、翻页、缩放和下载原件。

建议用 **EmbedPDF 2.15.1（PDFium/WASM）做首选原型**，以 **React-PDF 11.0.0（PDF.js 6.3.289）做对照**。旧版使用的 PDF.js 5.4.296 早于两项可复现的中文渲染修复，值得用新版本重新测。如果新版在实际样本上已经通过且加载成本更低，可以保留 React-PDF。暂未拿到旧站出错的简历原件，以下是公开证据和验收计划，没有实测出两者的兼容率。 [EmbedPDF 2.15.1](https://github.com/embedpdf/embed-pdf-viewer/releases/tag/v2.15.1) · [React-PDF 11.0.0](https://github.com/wojtekmaj/react-pdf/releases/tag/v11.0.0) · [PDF.js 5.4.530](https://github.com/mozilla/pdf.js/releases/tag/v5.4.530)

## 已知问题及处理结果

这里的 `react-pdf` 是 `wojtekmaj/react-pdf`，用 PDF.js 显示现成文件；同名的 [`@react-pdf/renderer`](https://github.com/diegomura/react-pdf) 用来生成 PDF。旧站的 `PdfPreviewDialog` 和 `PDFViewer` 已从 unpkg 配置 CMap 和标准字体，并导入了 `TextLayer.css`；两处列出的文档配置均没有 `wasmUrl`。是否曾请求失败、是否遇到受影响的图片编码、以及出错是否发生在画布或文本层，都要用原件确认。 [React-PDF 文档：非拉丁字符、图片解码、标准字体](https://github.com/wojtekmaj/react-pdf#support-for-non-latin-characters)

## 候选方案

| 方案                   | 适用性和限制                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **EmbedPDF**           | MIT，使用和 Chrome 原生查看器同源的 PDFium，但 WASM 构建、字体回退和引擎版本可能不同。用预制版快速比画质；首版需要接现有弹窗和工具栏时，用 headless 的渲染、滚动及缩放插件。默认从 CDN 加载 WASM，支持用 `wasmUrl` 自托管。公开的字体包安装体积 [#615](https://github.com/embedpdf/embed-pdf-viewer/issues/615)、v2 PDFium 基线 [#825](https://github.com/embedpdf/embed-pdf-viewer/issues/825) 和适应页面时缩放抖动 [#904](https://github.com/embedpdf/embed-pdf-viewer/issues/904) 仍开放；安装体积和实际网络传输分别量。 [React 文档](https://www.embedpdf.com/docs/react) · [引擎配置](https://www.embedpdf.com/docs/react/headless/engine) |
| **React-PDF 11**       | 保留 React 组件和 PDF.js，能测出升级引擎和资源配置本身是否够用。直接用 PDF.js，或采用 [React PDF Kit](https://github.com/react-pdf-kit/react-pdf-viewer)，主要换界面和集成层；后者默认 PDF.js 5.4.530，商业使用需授权。旧的 [`@react-pdf-viewer/core`](https://github.com/react-pdf-viewer/react-pdf-viewer) 仓库已归档。                                                                                                                                                                                                                                                                                                                       |
| **`@pdfrx/react`**     | MIT，另一套 PDFium/WASM 封装，有现成 React UI 和 headless hooks，可自托管 worker 和 WASM。若 EmbedPDF 的工具栏集成或移动端交互不合适，可作第二个 PDFium 候选；因为核心相同，不能假定会修掉同一份 PDF 的引擎问题。 [项目及 API](https://github.com/espresso3389/pdfrx_web) · [引擎文档](https://espresso3389.github.io/pdfrx_web/modules/_pdfrx_engine.html)                                                                                                                                                                                                                                                                                     |
| **其他引擎或更多格式** | [MuPDF.js](https://mupdf.readthedocs.io/en/latest/guide/using-with-javascript.html) 是独立的 WASM 引擎，需自行组装查看器，并评估 [AGPL 或商业许可](https://mupdf.readthedocs.io/en/1.28.5/license.html)。未来确定支持 Word 时再评估 [Apryse](https://docs.apryse.com/web/guides/file-format-support)（Office 转换是授权附加项）或 [docMentis](https://www.docmentis.com/docs/guide/quick-start)（浏览器内支持 PDF、DOCX 和图片，免费运行需连厂商域名计量）。                                                                                                                                                                                    |

## 如何做出决定

1. **拿同一批文件做对照。** 最优先用旧站异常原件在授权环境里复现，不把候选人简历上传到公共 demo。再加 PDF.js 两个公开 issue 的附件，以及用虚构资料从 Word/WPS、Google Docs 和常用模板工具导出的简历。样本至少包括中英混排、嵌入及未嵌入中文字体、两栏带图标和照片、多页、含 JPEG 2000/JBIG2 的扫描页。以本地 Acrobat 和 Chrome 原生查看作参考，并对比旧版、React-PDF 11 与 EmbedPDF。
2. **逐页看内容，实测交互。** 在 Chrome/Edge、Firefox、macOS Safari、iOS Safari 和 Android Chrome 用相同文件检查适应宽度和放大后：不漏字、不乱码、不丢照片或整页、不重叠；页数正确，翻页、缩放和下载可用。字号边缘的抗锯齿差异不作为失败。记录冷启动首屏耗时和实际下载量；加密或损坏文件至少显示明确错误，并保留下载原件的入口。
3. **在真实部署验证权限和资源。** 点击后才在浏览器导入查看器及其 worker/WASM，TanStack Start 用客户端边界。API 按工作区和上传条目 ID（`row.id`）授权；文件已被接受就可从私有 R2 通过现有 Files SDK 读取原件，无需等待生成 `resumeId`。预览和下载共享授权，下载保留原文件名。EmbedPDF v2 的 URL 读取文档说明默认不发 Cookie、整文件读取：同源会话需验证 `requestOptions.credentials: 'same-origin'`，或由应用先授权获取字节再用 `openDocumentBuffer`。验证退出和跨工作区后无法读取，并通过网络面板确认 WASM 和用到的回退字体可从本站加载。 [TanStack Start 执行边界](https://tanstack.com/start/latest/docs/framework/react/guide/execution-model) · [当前存储实现](../../apps/api/src/modules/ats/storage.ts) · [EmbedPDF URL 读取](https://www.embedpdf.com/docs/engines/document-lifecycle/open-document-url) · [文档管理器](https://www.embedpdf.com/docs/react/headless/plugins/plugin-document-manager) · [自托管资源](https://www.embedpdf.com/docs/snippet/airgapped)
