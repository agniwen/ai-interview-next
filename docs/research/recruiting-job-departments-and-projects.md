调研日期 2026-11-06。以下是官方帮助文档、公开 API 与产品资料所描述的流程。涉及必填规则时，区分产品界面、API 和租户策略。

## 招聘流程里的几种记录

可以把常见流程拆成几步。招聘人员和用人经理先对齐职责、要求与面试标准，有编制审批时先确认名额。随后创建或开放招聘岗位，按需要发布招聘广告、主动寻访或接收简历。人选进入具体岗位的流程后，按这次应聘推进筛选、面试、反馈和录用。对未定岗的人选，可以先保存资料或放进人才池，后续再进入具体岗位。各产品对开放岗位、审批和公开发布的要求各有差异。 [Metaview 岗位需求会](https://support.metaview.ai/notes/conversation-details) · [Ashby 建岗](https://docs.ashbyhq.com/creating-and-opening-jobs) · [Ashby 编制管理](https://docs.ashbyhq.com/openings-management) · [Ashby Projects](https://docs.ashbyhq.com/projects) · [Greenhouse 新建应聘 API](https://harvestdocs.greenhouse.io/reference/post_v3-applications)

## 部门和项目何时需要关联

**部门取决于组织流程。** Ashby 的建岗向导要求预先配置并选定部门和地点。Gem ATS 的建岗文档把部门列为可选，部门可用于按职能组织岗位和汇总报表。Greenhouse 的 Harvest v3 建岗 API 允许省略 `department_id`，职位也可后补部门。有部门专属审批时，后补部门需要手动应用相应审批。Moka 的创建职位 API 将 `departmentCode`、`pipelineId`、`headcountIds` 和招聘协作成员列为可选。API 字段的可选性仅说明接口约束，各租户的产品界面可有自己的政策。 [Ashby 建岗](https://docs.ashbyhq.com/creating-and-opening-jobs) · [Gem 建岗](https://help.gem.com/databases/gem-help-center/gem-ats-create-a-job) · [Gem 部门管理](https://help.gem.com/databases/gem-help-center/gem-ats-create-and-edit-departments) · [Greenhouse 建岗 API](https://harvestdocs.greenhouse.io/reference/post_v3-jobs) · [Greenhouse 部门与办公地点](https://support.greenhouse.io/hc/en-us/articles/360029591631-Office-and-department-dependent-workflows) · [Moka 建岗 API](https://mokahr.dochelp.cn/d/1687298468797771777.html)

## 招聘项目实际怎么运作

**Moka 校招项目统一管理一批岗位。** 管理员先建项目，再把已有职位加入。一个项目可加多个职位，一个职位只能加入一个项目。手册区分了用于记录的项目有效期和招聘时间设置，前者本身不自动控制流程，后者在项目与职位都有设置时以项目为准。项目可配置毕业时间提示、投递限制，以及在开启全局自动锁定后使用项目级候选人锁定。Moka 的校招介绍还描述了按项目推进和复盘数据的用法。 [Moka 管理员手册 §10.6](https://mokahr.moyincloud.com/d/1958812226527170561.html) · [Moka 校招项目介绍](https://www.mokahr.com/blog/9400.html)

**飞书招聘把项目做成可开启的管理维度。** 管理员在「项目设置 → 项目功能设置」开启社招项目管理，再在「项目管理」新建项目并选择社招职位类型。校招需要在校招职位字段管理里显示「项目」，可授权校招负责人管理项目。项目设置可填写名称、职位类型、项目管理员和投递职位数上限。项目列表显示关联职位数和启停状态。HR 在建岗时选一个项目，建岗截图未把该字段标为必填，公开 SDK 也将它建模为单值 `subject_id`。职位列表、候选人列表、人才库和报表可以按项目筛选。 [飞书招聘管理员入门手册「校招／社招相关配置」](https://www.feishu.cn/hc/zh-CN/articles/731255043228) · [飞书招聘 HR 入门手册 §2.4](https://www.feishu.cn/hc/zh-CN/articles/381040174542) · [新建职位模型](https://github.com/larksuite/oapi-sdk-go/blob/v3.12.2/service/hire/v1/model.go#L13410)

飞书创建投递的公开接口接收人才 ID 和职位 ID。招聘流程、面试评价、Offer 审批和招聘协作角色在职位上配置。校招可另启用志愿排序和项目内投递次数限制。公开资料未说明停用项目是否影响正在推进的应聘，也未说明岗位换项目后历史报表按哪个项目统计。 [飞书招聘管理员入门手册](https://www.feishu.cn/hc/zh-CN/articles/731255043228) · [飞书招聘 HR 入门手册](https://www.feishu.cn/hc/zh-CN/articles/381040174542) · [创建投递模型](https://github.com/larksuite/oapi-sdk-go/blob/v3.12.2/service/hire/v1/model.go#L56958)

**北森有按共享流程建项目的案例。** 其公开案例把使用同一招聘流程的职位放到一起，例如将非技术校招职位归入共同流程。该案例能说明项目用来组织相似岗位，无法确认当前产品的通用关联规则。 [北森集团招聘案例](https://www.beisen.com/res/366.html)

**SAP 用父招聘需求做统一入口。** SuccessFactors 可发布长期有效的 Evergreen Requisition，让候选人先投一个宽口径的方向。一个父需求可关联多个具体子需求，每个子需求最多有一个父需求。岗位和地点明确后，招聘人员可以把候选人转入对应子需求，该动作会在子需求下创建应聘。Dynamics 365 的 Recruitment Project 则记录特定部门和岗位的一次招聘计划，可以覆盖多个名额，从该项目广告收到的投递自动关联项目。 [SAP 父子需求](https://help.sap.com/docs/successfactors-recruiting/recruiting-in-sap-successfactors-test-script/add-child-job-requisition-to-evergreen-job-requisition-optional-c1c787752c7345f69c96323391d31f5b) · [SAP 转为应聘](https://help.sap.com/docs/successfactors-recruiting/setting-up-and-maintaining-sap-successfactors-recruiting/forward-as-applicant) · [Dynamics 365 招聘项目](https://learn.microsoft.com/en-us/dynamics365/fin-ops-core/fin-ops/hr/manage-recruiting-process)

**LinkedIn Recruiter 的项目还是协作和统计边界。** 项目把寻访结果和投递集中起来，招聘经理可以拥有仅查看或推进候选人等不同权限。同一个项目先后发布多个广告时，项目内展示的投递数、曝光和花费会累计。需要分开统计时，LinkedIn 建议为每个广告建独立项目。 [LinkedIn 发职位](https://www.linkedin.com/help/linkedin/answer/a415043) · [项目权限](https://www.linkedin.com/help/recruiter/answer/a481618) · [复用项目的统计规则](https://www.linkedin.com/help/recruiter/answer/a1458194)

如果 Sainoa 要支持「2027 秋招」这类批次，可以先让项目包含多个岗位，岗位可不选项目，每个岗位至多选一个。项目页显示所属岗位和应聘进度，已有的应聘、面试和评分继续按具体岗位记录。同一批次里有人投两个岗位时，报表可以分别显示候选人数和应聘数。要支持先报一个方向、筛选后才分岗时，再设计项目报名和转入岗位的流程。

## Metaview 怎么做

- **主动寻访从搜索开始。** Sourcing 的公开入口接受自然语言描述，也可以附 JD 或从需求沟通会记录生成初始搜索。招聘人员确认可编辑的理想候选人画像（ICP）后，Agent 搜索并给出人选，后续反馈用于校准。搜索可保留 ICP 的历史版本，也可把入选人送入已连接的 ATS。若搜索匹配到尚未配置筛选的 ATS 岗位，Metaview 可以用搜索的 ICP 作为新筛选的上下文。公开文档把这类记录称为搜索或 Agent 会话。 [Metaview Sourcing](https://support.metaview.ai/sourcing/overview) · [Sourcing 指南](https://support.metaview.ai/guides/tutorials/sourcing-guide)
- **简历筛选有两条入口。** Application Review 可以选已连接 ATS 的岗位与招聘阶段，也可命名一次筛选、提供岗位上下文并直接上传 PDF 或 Word 简历。接入 ATS 时会读取职位发布内容及关联的评分卡或投递问题。两种入口都可以补充 JD、能力框架和用人经理的沟通记录，先确认 ICP，再按标准给出匹配理由和分组。支持的 ATS 和权限决定哪些推进或拒绝动作可回写。直传模式的决定保存在 Metaview。 [Metaview Application Review](https://support.metaview.ai/application-review/overview) · [筛选集成与权限](https://support.metaview.ai/application-review/application-review-setup)
- **组织数据来自 ATS，岗位成员参与协作。** 以 Greenhouse 集成为例，Metaview 可读取岗位、部门、地点及招聘阶段等数据，并按授权回写应聘推进、面试记录等。筛选访问可来自 ATS 岗位的招聘团队、管理员权限或显式分享。面试记录还有单独的规则。按岗位角色授予面试访问时，需要通话已匹配到 ATS 应聘，并且用户已在 Metaview 工作区内。 [Greenhouse 集成说明](https://support.greenhouse.io/hc/en-us/articles/55720525030811-Metaview-integration) · [Metaview 筛选权限](https://support.metaview.ai/application-review/application-review-setup) · [Metaview 面试访问权限](https://support.metaview.ai/notes/access)
- **岗位上下文贯穿多种 AI 工作。** Job Posts 可以从空白、需求沟通会、模板或既有文档起草招聘文案。Interview Notes 可以利用岗位说明、简历、历史面试和 ATS 评分卡生成记录。Workspace Profile 另存可复用的岗位类别资料，例如后端工程师，与某次具体招聘对应不同粒度。 [Metaview Job Posts](https://support.metaview.ai/job-posts/overview) · [Metaview Interview Notes](https://www.metaview.ai/interview-notes) · [Metaview Workspace Profile](https://support.metaview.ai/account-management/workspace-profile)

据此推断，Sainoa 更值得借鉴的是用一份岗位上下文衔接简历评价和面试，并在进入正式招聘时选定岗位。Metaview 公开资料覆盖上述操作流程，其内部表结构及实体之间的完整关系没有公开确认。

## Sainoa 现状和演进顺序

当前 `Job` 存在工作区内，包含 ID、名称、岗位要求和创建时间，创建表单要求名称和岗位要求。`Application` 必须关联同一工作区中的候选人和岗位，同一候选人在同一岗位同时只有一条进行中的应聘。简历可以先上传和解析，建立应聘后再进行岗位评价。评价保留实际使用的简历版本和岗位要求快照。 [岗位表单](../../apps/web/src/components/features/ats/jobs-page.tsx#L38) · [ATS 数据结构](../../packages/db/src/schema/ats.ts#L120) · [应聘与面试 ADR](../adr/0004-ats-candidates-resumes-and-applications.md#应聘与面试)

1. **先完善岗位流程。** 沿用工作区直接建岗和简历先入库的路径。有暂停接收新应聘或隐藏历史岗位的需求时，先定义开放、关闭或归档各自对现有应聘的影响。招聘人员可以把岗位要求作为简历评价和面试准备的共同输入，并继续保留每次评价的依据。 [Greenhouse 关闭岗位](https://support.greenhouse.io/hc/en-us/articles/360025499691-Close-a-job) · [Sainoa 应聘与面试 ADR](../adr/0004-ats-candidates-resumes-and-applications.md#应聘与面试)
2. **按实际使用增加归属和协作。** 有跨部门筛选或统计时，可以先让每个岗位选填一个工作区内的主部门。需要让用人经理看进度、让面试官填反馈时，按岗位定义招聘团队和访问范围。客户明确要按部门审批时，再决定哪一步要求选定部门，例如提交审批或开放招聘。 [Greenhouse 部门与办公地点](https://support.greenhouse.io/hc/en-us/articles/360029591631-Office-and-department-dependent-workflows) · [Metaview 筛选权限](https://support.metaview.ai/application-review/application-review-setup)
3. **出现独立流程再增加记录。** 春招等需要多个岗位共用周期和报表时，定义招聘批次。需要长期储备、跨岗位复用人选时，定义人才池。需要申请或审批招聘计划时，定义招聘需求。需要逐一分配和核销编制时，再单独记录名额。业务项目只用于说明岗位背景时，可直接写进岗位要求。 [Moka 校招项目公告](https://www.mokahr.com/blog/9400.html) · [Gem Projects](https://help.gem.com/external/gem-ats-the-sourcing-tab) · [Lever Requisitions API](https://hire.lever.co/developer/documentation#requisitions) · [Ashby 编制管理](https://docs.ashbyhq.com/openings-management)
