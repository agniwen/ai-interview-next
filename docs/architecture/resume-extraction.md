# 简历字段提取

第一版结构化提取服务于候选人查重、候选人档案预填、岗位匹配和面试准备。人才库的精确筛选条件单独决定。简历解析结果保留提交时的内容，候选人档案保存当前采用的信息。

## 字段范围

| 字段组         | 提取内容                                                   |
| -------------- | ---------------------------------------------------------- |
| 身份和联系方式 | 姓名、手机号、邮箱、明确写出的现居城市、职业主页或作品链接 |
| 工作经历       | 公司、职务、起止时间、在职情况、职责和成果                 |
| 教育经历       | 学校、学历或学位、专业、起止时间                           |
| 项目经历       | 项目名称、担任角色、起止时间、贡献和成果                   |
| 技能           | 原文点名的技能、工具和技术，包括经历正文明确提到的技能     |
| 证书和语言     | 证书名称、签发机构、取得时间，以及明确声明的语言和水平     |

一份简历可以包含多条工作经历、教育经历、项目经历和证书。手机号、邮箱、职业链接、技能和语言也可有多项。结构化结果保留同类信息的全部条目。

结构化结果最外层的 `version` 为必填，当前格式为 `1`。其余提取字段都可以省略或为 `null`，包括整个字段组、列表、条目中的属性和原文证据。序列化为 JSON 时，值为 `undefined` 的对象字段省略。

工作经历按任职拆分。简历在同一家公司下分别列出两个职位时，保留两条经历。若原文只给出在该公司的总任职时间，各职位的起止时间仍为未知。教育经历按一段就读或一个学位拆分，项目和证书各按原文条目记录。

## 任职结构与补充字段

同一雇主的一段连续任职用一个条目保存正式职称及总任期。原文单独写出的分阶段角色放在该条目的 `stages` 中，使用各自的职称和任期。展示任职数量时，已有阶段的条目按阶段数计，其他条目按一条计。

| 字段组       | 提取内容                                                       |
| ------------ | -------------------------------------------------------------- |
| 求职目标     | 候选人明确声明的目标岗位，与应聘岗位分开                       |
| 职业自述     | 简历自我介绍中的职业要点                                       |
| 自报经验年限 | 原文给出的经验范围、年数及其限定词，与由履历计算的年限分开     |
| 任职背景     | 部门、工作地点、工作模式、下属规模和汇报对象，按任职或阶段记录 |
| 项目技术栈   | 明确用于某个项目的技术与工具，随该项目保存                     |
| 荣誉         | 明确具名的表彰或奖项，授予方和日期有原文依据时填写             |

主修课程、离职动机、年龄、出生日期、性别、婚育、籍贯和户口仍可在原简历中查看。

任职描述中单独命名且有具体内容的项目也可以提取。项目技术栈从该项目的描述取得，整份简历的技能仍可单独提取。

## 原文事实

提取结果只包含有原文依据的信息。日期保留原文提供的精度，例如「2022 年」只精确到年。「至今」表示仍在任，结束时间缺失或为 `null` 表示未知。最近任职公司可以从工作经历派生，累计工作年限和技能熟练度由各自的计算或评估规则处理。

经历或资格在能提取到证据时保留可定位的原文片段，能可靠定位到 PDF 页时一并记录页码。每个参与身份判断的联系方式单独保留证据。手机号证据应能看出号码属于谁，以及原文是否将它标为首选。

## 候选人档案预填

新建档案时可预填姓名和能唯一选定的本人手机号、邮箱。邮箱只有一项或明确指定了唯一首选时可预填，否则由招聘人员选择。已有档案的姓名、手机号和邮箱由招聘人员确认后更新。

缺少姓名的简历可以接收和解析。匹配到已有候选人时沿用现有档案。需要新建档案时，投递待招聘人员补录姓名后再关联。

## 最近任职公司

最近任职公司从已确定归属、包含工作经历的最新简历版本派生。版本按首次登记时间排序，同一份 PDF 重投时沿用原版本。优先采用明确仍在任的经历，多段仍在任时按开始时间判断，其余按结束时间判断。日期不足以确定唯一公司时留空。完整履历随各自的简历保留。

## 手机号匹配

用于自动查重的号码必须明确属于候选人本人且可以归一化。只有一个本人号码时，可以采用该号码。多个本人号码中只有明确指定的唯一首选号码可以用于自动查重。其余号码保留在简历解析结果中，PDF 哈希仍按[候选人查重规则](./candidate-matching.md)参与匹配。
