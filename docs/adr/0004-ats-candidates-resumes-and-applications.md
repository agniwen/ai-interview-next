# ATS 的候选人、简历与应聘记录

Sainoa 在工作区内分别管理候选人、简历和应聘记录。同一个人可以提交多份简历，也可以参与多个岗位的招聘流程。三者分别记录当前人物档案、提交时的材料和某次应聘的进度，方便更正归属，同时保留招聘历史。

## 上传与解析

用户可以批量上传简历，每个上传条目接收一份 PDF 并独立处理。上传后先建立或复用简历记录（`Resume`），解析完成后再识别候选人（`Candidate`）。PDF 文本适配器返回 `{ text }`，简历处理层提取姓名、手机号、邮箱和履历。Markdown 和结构化字段都属于简历的解析结果，可以先随简历记录保存。候选人档案保存当前采用的联系方式，后续换号时，历史简历仍保留当时提取到的原始值。

第一版字段范围见[简历字段提取](../architecture/resume-extraction.md)。批量上传、队列及岗位评价的调度边界见[可移植的简历处理流程](./0005-portable-resume-processing.md)。

## 候选人查重

- 在当前工作区内，用 PDF 的 SHA-256 或归一化的候选人手机号匹配已有候选人。同一份 PDF 可以复用已有解析结果。手机号可以从 PDF 提取，前提是号码明确属于候选人本人。
- 手机号与 PDF 命中不同候选人时，本次应聘归手机号命中的人。招聘人员确认后，冲突的 PDF 才能用于本次面试。该确认只作用于本次应聘，后续上传仍按原有的 PDF 查重归属匹配。
- PDF 命中已有候选人、手机号未匹配到任何候选人时，先沿用已有候选人，经人工确认后再更新号码。确认换号后，新号参与自动匹配，旧号保留在历史记录里。
- 仅邮箱相同或履历语义相似时，系统照常接收投递并允许查看简历。向量在当前工作区内召回和排序疑似候选人。发面试邀请前，招聘人员须确认关联已有候选人或新建候选人。

## 更正简历归属

简历详情提供「更正归属」。招聘人员可以将选中的简历拆出为新候选人，或转移到已有候选人。整体合并候选人档案是独立操作。新档案可以用简历提取的字段预填。转移时可按姓名或手机号搜索目标，用掩码手机号和最近任职公司区分同名候选人。确认界面显示当前归属、目标归属、匹配依据和受影响的应聘记录。更正操作沿用简历 ID 和解析结果，记录操作人、原归属和新归属。

| 移出简历后的原档案                   | 处理方式                             |
| ------------------------------------ | ------------------------------------ |
| 还有其他简历                         | 保留原档案及其他简历。               |
| 没有简历，但还有应聘、面试或人工备注 | 保留原档案，显示「暂无简历」。       |
| 只剩本次导入自动生成的信息           | 归档原档案，保留操作记录并允许恢复。 |

明确更正归属后，后续上传同一份 PDF 会使用新的查重归属。如果误关联来自 PDF 提取的手机号，招聘人员可以停用这份 PDF 上的该条手机号匹配线索。原始提取值仍保存在简历里，其他简历继续按各自的手机号匹配。

## 应聘与面试

应聘记录（`Application`）对应一个候选人对一个岗位的一次招聘流程。候选人再次投递同一岗位时，进行中的应聘沿用原记录和面试进度。上一次应聘已结束时可以新建记录，历史结果继续保留。不同岗位各自维护应聘记录。

简历独立于岗位保存。岗位由应聘记录确定，简历进入该次招聘流程后成为应聘材料。只有关联了应聘、候选人已确定且简历解析完成，才会触发 AI 岗位评价。

加入招聘流程时，解析状态为「已完成」的简历可以作为应聘材料选择。选择材料时只选择简历，候选人信息可通过简历归属查询。同一份简历可以用于不同岗位的应聘，各条应聘可以并行推进并分别评分。

招聘人员在「招聘流程」页新建招聘记录时选择简历和岗位。也可以从「简历」页的操作列或原件预览选择「加入招聘」，此时只需选择岗位。两种入口都使用简历已有的候选人归属。归属待确认时，招聘人员先在简历页确认候选人，再建立应聘记录。同一候选人和岗位已有进行中的应聘时，新增简历作为该次应聘的材料。重复选择已关联的简历会沿用已有记录和评分。

将一条应聘转到其他岗位时，结束原应聘，在新岗位新建或复用进行中的应聘。原应聘保留面试、反馈和评价。每次结束应聘记录一条操作日志，记录时间、实际发起人、动作和业务结果。招聘人员触发的自动结束归于该招聘人员，系统独立发起时归于系统。日志记录已生效的业务操作。

面试轮次、反馈和评估归属相应的应聘记录。评估引用当时使用的简历版本和岗位要求，方便回看结论依据。更正简历归属时，招聘人员单独确认相关应聘是否也需要纠正。误关联的简历从当前面试材料中移除，已发生的面试和反馈保留在原应聘记录中。如果两个候选人在同一岗位都已有面试进度，由招聘人员分别处理两条记录。

## 面试阶段与轮次

以下为 2026-11-07 产品讨论中已确认的设计，尚不表示功能已实现。

面试是一个大阶段，在应聘详情中使用一个 Tab 承载，可包含多个轮次。每轮仅按「第几轮」标识，初面、复面、终面等称呼通过自由填写的标签表达，不设为固定轮次类别。

首轮面试由招聘人员手动创建，不因进入面试阶段而自动创建。后续轮次同样手动创建，须等前一轮正式评价全部提交或确认，且整体评价为通过或待定。新建时重新选择面试官、参加时间和标签，轮次编号自动递增。

创建面试时指定面试官。选择系统中的用户对应真人面试，可继续添加其他真人面试官；选择面试官 Agent 对应 AI 面试，只能选择一个 Agent。同一轮不能混选用户和 Agent。同一面试阶段内用面试官的选择表达面试方式，不要求按固定的 AI 初面、真人复面顺序推进。

真人面试和 AI 面试均在 Sainoa 内通过 LiveKit 进行，支持麦克风与可选摄像头。真人面试的双方可以音视频交流，AI 面试由 Agent 通过语音提问和回应。两种面试均保存录音及带说话人标记的逐字转录，用于回放和评价，开始前向参与者说明录音与转录。第一版不保存视频录像，摄像头画面仅用于实时交流。

面试材料直接使用本次招聘流程中绑定的材料。实际开始前沿用最新绑定材料；实际开始时保存本轮材料快照，AI 面试同时保存所选面试官 Agent 的配置快照。后续修改岗位要求、简历绑定或 Agent 配置，不改变历史面试及其评价所依据的内容。新建面试时可以设置参加时间和面试官，尚未开始时可以修改；开始后及结束后不再修改这些设置。

每轮生成候选人专属邀请链接，候选人无需登录即可访问。面试官通过面试官链接访问，必须登录、具有对应工作区的访问权限，并且是本轮指定面试官；仅拥有工作区访问权限不足以进入房间。

创建面试必须填写预约开始时间和入场截止时间。预约开始时间前 10 分钟才允许进入房间；入场到期后不能进入房间。到期时已在进行的面试不被强制关闭，入场截止时间不代表强制结束时间。

真人面试中，候选人或任一指定面试官首次进入房间即视为实际开始，无需另点开始按钮，也不要求双方到齐。因此即使仅面试官提前入房，面试也已开始，时间和面试官设置随即锁定。AI 面试由候选人在完成设备准备后点击开始，启动 Agent 并标记为进行中；准备状态不算实际开始。预约时间到达本身不触发开始。

结束面试只能由面试官侧确定，候选人只能离开房间，不能结束整场面试。真人面试由任一指定面试官点击结束，AI 面试由 Agent 完成访谈后执行结束。AI 面试结束后生成评价，再交指定确认人审阅，确认人无需在线等待整场面试。

面试官 Agent 是具有名称、说明和提示词的可复用配置，可供不同面试选择。它与某次面试会话分别存在。

AI 面试产生「通过／不通过／待定」结论，必须由创建面试时指定的确认人确认，默认确认人为创建者。确认人可以保留或修正 AI 结论，系统保留原始结论及修正记录。真人面试结束后，每位指定面试官提交本人评价即视为确认。其他成员的普通留言不计入必须完成的评价。

真人面试评价格式参考旧项目 `ai-interview`，包含结论、评级 A/B/C/D、专业技能（优／良／中／差）、整体评价、角色定位和薪资建议。结论和整体评价必填，其余选填；结论为「通过／待定／不通过」，判断理由写在整体评价中，不单设理由输入框。

AI 面试输出相同的评价字段，结论和整体评价必填，其他字段有依据时填写，无依据时允许留空。指定确认人可以修正这些字段后确认，保留原始 AI 输出与人工修正记录。

只有一位真人面试官时，该面试官的评价作为整体评价；有多位面试官时，按正式提交时间取首个非待定评价作为整体评价。先提交通过、后提交不通过时，整体仍为通过；先提交待定、后提交不通过时，整体为不通过。所有面试官均已提交且全部待定时，整体也为待定。

所有正式评价均提交或确认之后，才能推进下一轮面试或下一个大阶段。整体为通过或已确认的待定时允许继续推进；未提交或未确认的评价阻塞推进。整体评价为不通过时直接结束招聘流程，不允许继续推进；后续某一人的不通过不会覆盖此前已确定的整体通过结论。AI 面试以人工确认后的结论作为整体评价。

真人面试评价允许保存和修改草稿，正式提交即确认并锁定，之后不能修改。AI 评价允许在人工确认前修正，确认后锁定，并保留 AI 原始结论与人工修正记录。

面试后的大阶段命名为「入职」，暂不实现。本轮不采用此前讨论中建议的独立 Offer 阶段。
